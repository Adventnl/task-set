29 September 2026: **no length limit on notes, and a phone pass.** (1) The 4,000-character cap (`MAX_CAPTURE_LENGTH`) is gone from the composer and event editor boxes and from the record validators, which had also made the Worker refuse, and the app drop on pull, any longer note. A record now only has to fit one Durable Object row (2 MB): `MAX_RECORD_BYTES` is 1.9 MB, checked in `saveLocal` (a too-large save stores nothing and shows a message beside the composer) and again in the Worker's push, which counts it as rejected instead of failing the batch. Because large notes were then possible, sync no longer assumes small ones: the outbox pushes in byte-budgeted batches, the push limit is `MAX_RECORD_BYTES` plus envelope (was 1 MB, which would have wedged sync permanently on one big paste), and pulls page by bytes as well as by count (`takeWithinBytes`, shared by both). Task and meeting titles stay at 200 characters. (2) The Android icon is a device-side matter: the installed app keeps the icon it was installed with and Chrome refreshes it lazily, so reinstalling is the reliable way; the site's manifest, icons, and service worker were checked and serve fresh files. The maskable icon's padding was a slightly darker red than the artwork, which framed it under a mask; it is regenerated from the supplied artwork with a seamless fill and the same glyph position. (3) Phone layout, found by measuring in Chromium at 412, 360, and 320 px wide with touch: the note actions are a bottom sheet on phones and touch screens (the popover cut off Delete on the newest note and covered the text); notes use the full width with the ⋯ button on the time line; every view opens at its top (Tasks and Calendar opened part-way down, hiding their first lines); Notes stays at the newest note when the keyboard or composer resizes it; an open search takes the header row (the title had wrapped to “Not / es”); a meeting page has an app bar with a full-width title; in a window under 600 px tall Coming up and the subtitle step aside (the feed had 93 px with the keyboard open on a 320 px phone, now 203); the GitHub repository list no longer scrolls inside the page; the dictation panel follows the newest words; save errors show beside the composer; the hidden composer on GitHub reserves no space. Desktop and tablet renders of the previous commit and this one are pixel-identical in light and dark (bar two stray antialiasing pixels) except Tasks, which now opens at its top. Tests: 140 (16 new).
